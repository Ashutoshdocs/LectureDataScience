Six ways to predict a number

Regression means predicting a quantity: a price, a delay in minutes, a temperature. All six algorithms do the same job. They differ in the shape of line they're allowed to draw through your data.

The equation familyLinear, multiple linear, polynomial. Learn a formula's numbers. Smooth, explainable, can extend beyond the data.
The tree familyDecision tree, random forest, gradient boosting. Learn yes/no questions. Flexible, but flat outside the data they saw.

Step 1 · The foundation

Linear regression: the best straight line

Every other algorithm on this page builds on one idea from here: measure how wrong you are, then make that number as small as possible.

price = m × size + b

The model has just two numbers to learn: the slope m (how much price rises per unit of size) and the intercept b (the starting price).

  1. Draw any line. For each house, the vertical gap between the dot and the line is the residual (the error).
  2. Square every residual (so negatives don't cancel positives) and average them. That's the mean squared error (MSE).
  3. Find the m and b that make MSE smallest. This is called least squares. For a straight line there's an exact formula; for big models, gradient descent nudges m and b downhill step by step.

Try it: move the sliders and watch the residual lines and the error. Then let the maths find the answer.

from sklearn.linear_model import LinearRegression
model = LinearRegression().fit(X, y)
model.coef_, model.intercept_   # m and b
Your MSE Best possible
Notice the miss: even the best straight line overshoots big houses and undershoots mid-size ones. The real pattern bends. A straight line can't, which is called underfitting. Polynomial regression (Step 3) fixes this.
Step 2 · More inputs

Multiple linear regression: one weight per column

Real prices depend on more than size. Multiple linear regression gives every input its own coefficient and adds the pieces up.

price = b₀ + b₁·size + b₂·bedrooms + b₃·age + b₄·near_metro
  1. Each coefficient is learned with the same least-squares rule as Step 1, just in more dimensions. Instead of a line, the model fits a flat plane (or hyperplane).
  2. A coefficient means: change this input by 1 while holding the others fixed, and the price moves by this much. That's what makes the model easy to explain.
  3. A negative coefficient pulls the price down. Here, every year of age costs ₹0.5 lakh.
Watch out for: inputs that move together (size and bedrooms) can make coefficients unstable, which is called multicollinearity. And it's still straight lines: each input's effect is the same at every value.
X = df[["size","bedrooms","age","near_metro"]]
LinearRegression().fit(X, df["price"])

Step 3 · Bending the line

Polynomial regression: curves, and the danger of too many

Add size², size³… as extra columns, then run ordinary linear regression on them. The line can now bend.

price = b₀ + b₁·x + b₂·x² + b₃·x³ + … + bd·xd
  1. Pick a degree d. Degree 1 is a straight line, degree 2 is one bend, degree 3 two bends.
  2. It's still "linear" regression, because the model is linear in the coefficients. You've only invented new columns.
  3. Judge it on test data it never saw. Training error always falls as degree rises; test error falls, then climbs. The climb is overfitting: the curve memorises noise.

Step 4 · A different idea

Decision tree regressor: twenty questions

Forget equations. A tree splits houses into groups with yes/no questions, then predicts the average price of each group.

  1. Try every possible split, like "size < 4.3?". For each, measure how similar the prices are on each side (variance, i.e. MSE around each side's average).
  2. Keep the split that makes both sides most uniform. Then repeat inside each side. This greedy search builds the tree.
  3. Stop at a max depth or when a group gets too small. Each final group (leaf) predicts its average.

The prediction is a staircase. Deeper trees have more, smaller steps; too deep and each step hugs a single house (overfitting).

Step 5 · Wisdom of the crowd

Random forest regressor: many trees, averaged

One deep tree is jumpy. Train lots of different deep trees and average their answers: the jumps cancel out, the real pattern stays.

  1. Bootstrap: each tree gets its own random sample of the training rows, drawn with replacement. Some houses appear twice, some not at all.
  2. Random features: at each split, a tree may only consider a random subset of the columns. This keeps trees different from each other. (Our demo has one column, so only step 1 shows.)
  3. Average: the forest's prediction is the mean of all trees' predictions. This is called bagging.

Trees are trained independently, so they can run in parallel. Random forest works well with little tuning, which makes it a great default.

from sklearn.ensemble import RandomForestRegressor
RandomForestRegressor(n_estimators=200, max_features="sqrt")

Step 6 · Learning from mistakes

Gradient boosting regressor: fix the errors, one small tree at a time

Random forest builds trees side by side. Boosting builds them in a line: each new tree studies what the model so far got wrong.

  1. Start with a dumb guess: the average price of all houses.
  2. Compute the residuals (actual − predicted). Train a small tree to predict those residuals.
  3. Add that tree's output, shrunk by the learning rate (e.g. 0.1), to the model. Repeat for hundreds of rounds.
Fnew(x) = Fold(x) + learning_rate × treeresiduals(x)

"Gradient" because, for squared error, residuals are exactly the direction that lowers the loss fastest. A small learning rate needs more rounds but generalises better. Too many rounds will eventually overfit, so practitioners stop early using validation data.

from sklearn.ensemble import GradientBoostingRegressor
GradientBoostingRegressor(n_estimators=300, learning_rate=0.05, max_depth=3)
