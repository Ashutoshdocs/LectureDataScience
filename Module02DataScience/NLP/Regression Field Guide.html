What is regression?

Regression means predicting a number from some information you already have. If the answer is a quantity (price, weight, score, minutes), it's a regression problem. If the answer is a category (spam / not spam, cat / dog), it's a classification problem instead.

Every regression model follows the same idea: look at many past examples where we know the answer, find the pattern, then use that pattern on new cases.

We compare predictions with the real answers. Here are 4 houses (prices in ₹ lakh). The model's guesses are close but not perfect.

MAE: Mean Absolute ErrorAverage size of the mistakes.
(2+3+1+4) / 4 = 2.5
"On average we're off by ₹2.5 lakh."
MSE: Mean Squared ErrorSquare each error, then average. Big mistakes count much more.
(4+9+1+16) / 4 = 7.5
RMSE: Root MSESquare root of MSE, back in the original units.

Lower MAE / MSE / RMSE is better. Higher R² is better. Most models learn by trying to make MSE as small as possible.

Model 1 of 6

Linear Regression

Draw the one straight line that passes as close as possible to all the dots.

Analogy: put a ruler on a scatter plot and wiggle it until it looks like the best fit. Linear regression does exactly that, but with maths instead of eyeballing, so everyone gets the same answer.

The equation

ŷ = m × x + b

x is the input (house size). m is the slope: how much the price rises for each extra square foot. b is the intercept: where the line crosses zero. Training means finding the best m and b.

How it learns

  1. Start with any line.
  2. For every dot, measure the vertical gap between the dot and the line (the residual).
  3. Square each gap and average them. That's the MSE.
  4. Choose m and b that make the MSE as small as possible. There's an exact formula for this, called least squares.

Worked example

Three houses: 1,000 sq ft → ₹45 L, 1,500 → ₹60 L, 2,000 → ₹75 L.

Each extra 500 sq ft adds ₹15 L, so the slope is 15 / 500 = 0.03 lakh per sq ft. Plug in the first house: 45 = 0.03 × 1000 + b, so b = 15.

price = 0.03 × size + 15

Prediction for a 1,800 sq ft house: 0.03 × 1800 + 15 = ₹69 lakh.

# pip install scikit-learn
from sklearn.linear_model import LinearRegression

X = [[1000], [1500], [2000]]   # house size (one feature, so each row has 1 value)
y = [45, 60, 75]               # price in lakh

model = LinearRegression()
model.fit(X, y)                # learn m and b

print(model.coef_[0])          # slope m      → 0.03
print(model.intercept_)        # intercept b  → 15.0
print(model.predict([[1800]])) # → [69.]

Good at

  • Very easy to understand and explain
  • Trains instantly, even on huge data
  • Great baseline to compare other models against

Watch out for

  • Only draws straight lines
  • Outliers can pull the line a lot
  • Uses only one input

Quick check: in price = 0.03 × size + 15, what does 0.03 mean?

Model 2 of 6

Multiple Linear Regression

Same idea as linear regression, but using several inputs at once. Each input gets its own weight.

Analogy: a restaurant bill. The total is a fixed table charge plus a price for each item: so much per dosa, so much per coffee. The model learns the "price" (weight) of each feature, then adds everything up.

The equation

ŷ = b₀ + b₁·size + b₂·bedrooms + b₃·age + b₄·near_metro

Each b is a coefficient. A positive one pushes the price up, a negative one pulls it down. Training finds all of them together, again by minimising MSE.

Real price depends on more than size. A 1,200 sq ft flat next to a metro station is worth more than the same flat 10 km away. One input can't capture that; several inputs can.

Worked example

A 1,400 sq ft, 3-bedroom, 4-year-old flat near a metro:

8 + 0.025×1400 + 4×3 − 0.6×4 + 6×1 = 8 + 35 + 12 − 2.4 + 6 = ₹58.6 L

Reading the coefficients: each year of age knocks ₹0.6 L off, and being near a metro adds ₹6 L, with everything else kept the same. That "everything else the same" part is what makes multiple regression useful for understanding.

import pandas as pd
from sklearn.linear_model import LinearRegression

df = pd.DataFrame({
    "size":       [900, 1400, 2100, 1100],
    "bedrooms":   [2, 3, 3, 2],
    "age":        [10, 4, 15, 1],
    "near_metro": [0, 1, 0, 1],
    "price":      [32, 60, 64, 49],
})
X = df[["size", "bedrooms", "age", "near_metro"]]   # several columns now
y = df["price"]

model = LinearRegression().fit(X, y)
for name, coef in zip(X.columns, model.coef_):
    print(name, round(coef, 3))                     # one weight per feature
print("intercept", model.intercept_)

Real projects need many more rows than columns. With 4 rows and 4 features the numbers above are only for illustration.

Good at

  • Uses many inputs together
  • Each coefficient has a clear meaning
  • Fast and simple

Watch out for

  • Still assumes straight-line effects
  • Features on very different scales or strongly related to each other can make coefficients misleading
  • Can't capture "this matters only when that is true" on its own

Quick check: the coefficient for "age" is −0.6. What does that tell you?

Model 3 of 6

Polynomial Regression

Let the line bend by adding x², x³ and higher powers as extra inputs.

Analogy: swap the stiff ruler for a bendy wire. A little bend fits a curve nicely. Too much bend and the wire snakes through every single dot, including the random ones.

The equation

ŷ = b₀ + b₁x + b₂x² + b₃x³ + … + bdxd

The highest power, d, is called the degree. Degree 1 is a straight line, degree 2 is a U or ∩ shape, degree 3 can make an S.

Here's the neat trick: you create new columns (x², x³…) and then run ordinary multiple linear regression on them. The curve is new, the method is the same.

Our example: car speed vs fuel efficiency. Cars use fuel badly in slow traffic and at very high speed, and are most efficient around 50–70 km/h. A straight line can't show that rise and fall.

The most important lesson here

As the degree goes up, training error always falls, because a bendier curve can always get closer to the dots it has seen. Test error falls at first, then rises once the curve starts chasing noise. The best model is the one with the lowest test error, not training error. This is true for every model in this guide.

Worked example

Say training gives a degree-2 model: efficiency = −0.004·speed² + 0.48·speed + 7.6

At 60 km/h: −0.004×3600 + 0.48×60 + 7.6 = −14.4 + 28.8 + 7.6 = 22.0 km/l
At 110 km/h: −0.004×12100 + 0.48×110 + 7.6 = −48.4 + 52.8 + 7.6 = 12.0 km/l

The negative x² coefficient is what makes the curve bend down at both ends.

from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline

X = [[20], [40], [60], [80], [100], [120]]     # speed km/h
y = [15.6, 20.4, 22.0, 20.4, 15.6, 7.6]       # km per litre

# Step 1 turns x into [1, x, x²]; step 2 is plain linear regression
model = make_pipeline(PolynomialFeatures(degree=2), LinearRegression())
model.fit(X, y)

print(model.predict([[70]]))   # → about 21.6

Good at

  • Smooth curved relationships
  • Still simple: it's linear regression underneath

Watch out for

  • High degree overfits badly
  • Goes wild outside the range of the data
  • Number of columns explodes with many features

Quick check: degree 10 gives the lowest training error. Should you pick it?

Model 4 of 6

Decision Tree Regressor

Split the data with a series of yes/no questions, then predict the average of whatever group you land in.

Analogy: the game "20 Questions". "Is it hotter than 25 °C?" Yes. "Hotter than 33 °C?" No. "Then I'd guess about 170 ice creams." Every question narrows things down.

How it learns

  1. Look at every possible split (temp < 10, temp < 10.5, …).
  2. For each split, compute how well the two groups' averages predict their own members (the error).
  3. Keep the split that lowers the error the most.
  4. Repeat inside each group, until you hit a stopping rule such as max depth (how many questions in a row).
  5. Each final group is a leaf. Its prediction is the average of the training points inside it.

Our example for the next three models: daily temperature vs ice-cream cups sold at a shop. Sales are low on cold days, climb quickly between 20 and 30 °C, then level off.

Worked example

    
Six days: 12 °C → 45 cups, 16 °C → 55, 24 °C → 120, 27 °C → 150, 35 °C → 195, 40 °C → 205.

    
The tree tries splits and finds that temp < 20 °C separates the cold days best. Left group average: (45+55)/2 = 50. Right group: (120+150+195+205)/4 = 167.5.

    
At depth 2, the right group splits again at temp < 31 °C: (120+150)/2 = 135 and (195+205)/2 = 200.

    
A 29 °C day → not < 20 → is < 31 → predict 135 cups

  


  
from sklearn.tree import DecisionTreeRegressor, export_text

X = [[12], [16], [24], [27], [35], [40]]   # temperature °C
y = [45, 55, 120, 150, 195, 205]           # cups sold

tree = DecisionTreeRegressor(max_depth=2)  # at most 2 questions in a row
tree.fit(X, y)

print(export_text(tree, feature_names=["temp"]))  # see the rules
print(tree.predict([[29]]))                        # → [135.]


  

    
Good at
  • Handles curves and "only if" rules without extra work
  • Easy to read as plain if/else rules
  • No need to scale features

    
Watch out for
  • Deep trees overfit easily (try depth 8 above)
  • Predictions are jumpy steps
  • Small changes in data can change the whole tree
  • Can't predict beyond the highest value it has seen

Model 5 of 6

    
Random Forest Regressor

    
Grow many different decision trees, then average their predictions.

  

  
Analogy: guessing the number of sweets in a jar. One person's guess may be way off. Ask 100 people and average their guesses, and the result is usually very close. Each person's random mistakes cancel out. This is called the wisdom of the crowd.


  

    
How it learns

    
    
      
  1. Bootstrap: make a new dataset by randomly picking rows from the original, with replacement. Some rows appear twice, some not at all.
    2. 
      
  2. Train a decision tree on that dataset. When there are several features, each split may only look at a random subset of them.
    3. 
      
  3. Repeat to grow, say, 100 trees. Each one is a bit different because it saw different data.
    4. 
      
  4. To predict, ask every tree and take the average.
    5. 
    

    
The randomness is the point. Each tree overfits in its own direction, and averaging smooths those errors away. This combining of models is called bagging (bootstrap aggregating).

from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import train_test_split
from sklearn.metrics import mean_squared_error

# X: temperatures as [[t], [t], ...], y: cups sold
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)

forest = RandomForestRegressor(
    n_estimators=100,   # number of trees
    max_depth=None,     # let each tree grow fully; averaging controls overfitting
    random_state=0,
)
forest.fit(X_train, y_train)

pred = forest.predict(X_test)
print("Test RMSE:", mean_squared_error(y_test, pred) ** 0.5)


  

    
Good at
  • Usually much more accurate than one tree
  • Hard to overfit by adding more trees
  • Works well with little tuning, a strong default
  • Tells you which features matter most

    
Watch out for
  • Slower and bigger than a single tree
  • Harder to explain (100 trees, not 1 set of rules)
  • Still can't predict beyond the range of training data

Model 6 of 6

    
Gradient Boosting Regressor

    
Build small trees one at a time, each one trained to fix the mistakes left by all the trees before it.

  

  
Analogy: golf. Your first shot gets you near the hole. The second shot doesn't start from the tee; it starts from where the ball landed and aims at the remaining gap. Each shot is shorter and corrects what's left. Gradient boosting works the same way with prediction errors.


  

    
How it learns

    
    
      
  1. Start with a simple guess for everyone: the average of all targets.
    2. 
      
  2. Compute the residuals: actual minus current prediction. These are the mistakes.
    3. 
      
  3. Train a small tree to predict those residuals.
    4. 
      
  4. Add that tree's output to the current prediction, scaled down by the learning rate (e.g. × 0.1) so each step is cautious.
    5. 
      
  5. Repeat for many rounds. The residuals shrink every round.
    6. 
    

    
Random forest vs boosting: forest trees are independent and grown side by side, then averaged. Boosting trees are grown one after another, and each depends on the ones before it.

from sklearn.ensemble import GradientBoostingRegressor

gbr = GradientBoostingRegressor(
    n_estimators=200,    # number of rounds / small trees
    learning_rate=0.1,   # how big each correction step is
    max_depth=3,         # keep each tree small ("weak learner")
    random_state=0,
)
gbr.fit(X_train, y_train)
print(gbr.predict(X_test[:5]))

# Popular faster libraries using the same idea: XGBoost, LightGBM, CatBoost


  

    
Good at
  • Often the most accurate on spreadsheet-style data
  • Wins many data-science competitions
  • Flexible: handles complex patterns

    
Watch out for
  • Can overfit with too many rounds or a high learning rate
  • More settings to tune
  • Trees train one by one, so it can be slower

A sensible beginner workflow

    
    
      
  1. Split your data into training and test sets (for example 80% / 20%).
    2. 
      
  2. Fit a linear or multiple linear model first. This is your baseline.
    3. 
      
  3. Try a random forest. If it beats the baseline clearly, the pattern isn't straight.
    4. 
      
  4. Try gradient boosting and tune the learning rate and number of rounds.
    5. 
      
  5. Compare everything on the test set using RMSE or R². Choose the simplest model that's close to the best.
    6.
