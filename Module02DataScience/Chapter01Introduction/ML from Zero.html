Lesson 01 · The big ideas

What is Artificial Intelligence?

Artificial Intelligence (AI) is the broad field of making computers do things that normally need human intelligence: seeing, understanding language, making decisions, solving problems, learning from experience.

AI is an umbrella term. It includes simple rule-based systems (a chess program from the 1990s following hand-written strategies) and modern learning systems (ChatGPT, self-driving cars).

Analogy: "Transport" covers bicycles, cars and planes. "AI" similarly covers everything from a simple rule-based chatbot to a model that writes essays.

Two kinds of AI people talk about

Narrow AI (exists today)

Very good at one specific task. Face unlock, Google Maps traffic prediction, Netflix recommendations, chatbots.

General AI (not yet achieved)

A machine that can learn and do any intellectual task a human can, across all areas. Still a research goal.

Lesson 02 · The big ideas

What is Machine Learning?

Machine Learning (ML) is a part of AI where the computer learns patterns from data instead of being given step-by-step rules. Show it enough examples and it figures out the rule itself, then uses that rule on new cases it has never seen.

Analogy: how a child learns what a dog is. Nobody hands them a rulebook ("four legs, fur, tail…"). They see many dogs, someone says "dog" each time, and soon they recognise dogs they have never met.

Example: to predict house prices, you show the computer hundreds of houses with their size and actual price. It finds the pattern "bigger houses cost more, by roughly this much per square foot" and can then estimate a price for any new house.

Python · scikit-learn 
from sklearn.linear_model import LinearRegression

sizes  = [[650], [800], [1000], [1200], [1500], [1800], [2200], [2600]]   # sq ft
prices = [35, 48, 55, 70, 82, 100, 118, 140]                             # ₹ lakh

model = LinearRegression().fit(sizes, prices)   # learn the pattern
print(model.predict([[2000]]))                  # ≈ [108.] lakh
Lesson 03 · The big ideas

What is Deep Learning?

Deep Learning (DL) is a type of machine learning that uses artificial neural networks, loosely inspired by neurons in the brain. "Deep" means the network has many layers stacked on top of each other.

Each layer learns something a bit more complex than the previous one. In a face-recognition network:

Pixels→Layer 1: edges & lines→Layer 2: shapes (circles, corners)→Layer 3: parts (eyes, nose)→Output: "This is Priya"

Deep learning shines with unstructured data like images, audio and text, where it's hard for humans to describe the features. It needs a lot of data and computing power (usually GPUs). It powers voice assistants, Google Photos search, self-driving cars and ChatGPT.

The building block: one artificial neuron

A neuron takes inputs, multiplies each by a weight (how important it is), adds them up with a bias, and squashes the result into a number between 0 and 1. Training a network means finding good weights automatically. Here you can set them by hand.

from tensorflow import keras

model = keras.Sequential([
    keras.layers.Input(shape=(784,)),              # a 28×28 image = 784 pixels

Lesson 05 · The big ideas

Traditional Programming vs Machine Learning

This is the single most important idea in the course. The inputs and outputs swap places.

Traditional programming
Rules+Data→Answers

A programmer thinks hard and writes the rules. The computer applies them.

if temp_c: return temp_c * 1.8 + 32
Machine learning
Data+Answers→Rules

You give examples with the correct answers. The computer works out the rule.

(0→32), (10→50), (20→68)… ⇒ learns ×1.8 +32

When is ML better? When the rules are too complicated to write by hand. Nobody can write rules for "is this photo a cat?" or "is this email spam?" that cover every case. But we can easily collect thousands of labeled examples.

When is traditional programming better? When the rule is known and exact: calculating GST, sorting a list, converting units. Using ML there is overkill.

Lesson 06 · Data and models

Dataset, features and labels

ML starts with data, so we need three words:

  • Dataset: the whole collection of examples, usually a table. Each row is one example (one fruit, one customer, one email).
  • Features (inputs, often written X): the columns that describe each example. The clues.
  • Label (target, output, written y): the column with the answer we want the model to predict.
Analogy: a doctor diagnosing. The symptoms (fever, cough, age) are the features. The diagnosis (flu or not) is the label. Past patient records are the dataset.

The same dataset can serve different problems. What counts as a "label" depends on the question you ask. Good features matter a lot: colour helps tell apples from bananas, but the fruit's serial number would be useless.

Lesson 07 · Data and models

Training and testing data

Before training, we split the dataset into two parts:

  • Training set (usually 70–80%): the model learns from these examples.
  • Test set (20–30%): hidden during training, used only at the end to check how well the model works on data it has never seen.
Analogy: a teacher gives you practice questions (training set), but the final exam has new questions (test set). If the exam reused the practice questions, a student who simply memorized answers would score 100% without understanding anything.

That memorizing problem has a name: overfitting. The model does brilliantly on training data and badly on new data. The opposite, a model too simple to capture the pattern, is underfitting.

Lesson 09 · Data and models

Model training

A model is a formula with adjustable knobs called parameters (or weights). Training means turning those knobs until the model's predictions match the training labels as closely as possible. In Lesson 5 you did this by hand. Here the computer does it.

Training repeats a simple loop thousands of times:

1. Predict→2. Measure the error (the loss)→3. Nudge each knob in the direction that lowers the error→repeat

Step 3 is called gradient descent. The size of each nudge is the learning rate.

Analogy: walking down a foggy hill to the valley. You can't see the bottom, but you can feel which way the ground slopes under your feet, so you take a step downhill and repeat. Steps too small: it takes forever. Steps too large: you jump over the valley and end up higher on the other side.

Lesson 11 · Data and models

Batch vs real-time inference

Once a model is ready, there are two ways to run it:

Batch inference

Collect lots of inputs, then predict for all of them together on a schedule (every night, every hour). Cheap and efficient, but results are not instant.

Example: Netflix computes your "Top picks" overnight
Example: a bank scores all loan applications at 2 AM
Real-time (online) inference

Predict immediately, the moment each input arrives. Needed when a delay would be useless or costly. Needs servers always running.

Example: UPI fraud check while you pay
Example: Google Maps ETA, face unlock
Analogy: a dhobi who collects clothes all week and washes them in one big load on Sunday (batch), versus a dry-cleaner offering a 1-hour express service for each item (real-time).

In batch mode, a fraudulent payment might be caught after the money is already gone. That's why fraud detection is real-time, while recommendations (which can wait) are usually batch.

Lesson 12 · Types of learning

Supervised Learning

In supervised learning, every training example comes with the correct answer (a label). The model learns the mapping from features to label, like a student learning with a teacher who marks every answer. It is the most common type of ML.

Classification · predict a category

The label is a class.

Email → spam / not spam
X-ray → pneumonia / healthy
Photo → cat / dog / bird
Regression · predict a number

The label is a quantity.

House → ₹ 85 lakh
Tomorrow → 34 °C
Order → delivery in 27 min

Lesson 13 · Types of learning

Unsupervised Learning

In unsupervised learning, the data has no labels. Nobody tells the model the right answer. Its job is to discover hidden structure on its own: groups, patterns or unusual items.

Analogy: tip a box of mixed LEGO on the floor and ask a child to sort it. Nobody gives categories, yet they'll group by colour or size. The groups come from the data itself.
Clustering

Group similar items. Customer segments for marketing, grouping news articles by topic.

Anomaly detection

Find items that don't fit any pattern. Unusual network traffic, a faulty machine sensor.

Association

Find things that go together. "People who buy bread often buy butter" on shopping sites.

Dimensionality reduction

Compress many features into a few while keeping the important information (e.g. PCA).

The classic clustering algorithm is k-means: place k centres randomly, assign each point to its nearest centre, move each centre to the middle of its points, and repeat until nothing changes.

from sklearn.cluster import KMeans

Lesson 14 · Types of learning

Reinforcement Learning

In reinforcement learning (RL), an agent learns by trial and error inside an environment. It takes actions, receives rewards (good) or penalties (bad), and gradually learns a strategy, called a policy, that collects the most reward over time. There is no dataset of correct answers.

Analogy: training a puppy. You don't explain the rules. When it sits, it gets a treat (+ reward). When it chews your shoes, it gets a firm "no" (− penalty). After many tries, it learns what earns treats.
Agent→ action →Environment→ new state + reward →Agent learns↺

Famous examples: AlphaGo beating the world Go champion, robots learning to walk, game-playing AIs, and fine-tuning chatbots using human feedback (RLHF).
